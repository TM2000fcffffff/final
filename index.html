DAY 1

Claude Code와 컨텍스트 이해하기

첫날은 AI 코딩 도구 Claude Code와 친해지는 날입니다. Claude Code가 어떻게 일하는지, AI가 한 번에 기억하는 범위인 컨텍스트는 어떻게 관리하는지, 화면까지 다루는 Claude in Chrome·Computer Use는 무엇인지 알아보고, 말로 설명해서 홈페이지를 만드는 바이브 코딩을 직접 해 봅니다.

Claude Code란?

말로 시키면 직접 일하는 AI 코딩 도우미

Claude Code는 터미널·데스크톱 앱·VS Code 등에서 동작하는 AI 코딩 에이전트입니다. 답만 알려 주는 챗봇과 달리, 내 PC의 프로젝트 폴더에서 파일을 읽고, 고치고, 명령을 실행합니다.

  • 읽기·찾기 — 파일 열기, 키워드 검색
  • 쓰기·고치기 — 파일 만들기, 코드 수정
  • 실행 — 터미널 명령(git, npm 등) 실행
  • 확장 — MCP·스킬로 브라우저, DB 등 외부 도구 사용

일하는 방식: 에이전트 루프

  1. 요청 받기 — "메인 페이지에 카드 3개 만들어 줘"
  2. 상황 파악 — 관련 파일을 읽고 구조를 이해
  3. 계획 — 무엇을 어떻게 바꿀지 정함
  4. 실행 — 파일 수정, 명령 실행
  5. 확인 — 결과를 보고 틀리면 다시 고침

목표를 이룰 때까지 이 과정을 스스로 반복합니다.

어디서 쓰나요?

  • Claude 데스크톱 앱의 Code 탭 — 폴더를 고르고 바로 대화
  • 터미널 — 프로젝트 폴더에서 claude 실행
  • VS Code 등 에디터 확장

어디서 쓰든 하는 일은 같습니다. 작업할 폴더를 정하고, 하고 싶은 것을 말로 설명하면 됩니다.

권한 모드 (Shift+Tab로 전환)

  • 기본 — 파일 수정·명령 실행 전에 매번 물어봄
  • 자동 수락 — 파일 수정은 묻지 않고 바로 진행
  • Plan 모드 — 고치지 않고 계획만 세워 보여 줌 → 큰 작업 전에 유용

처음엔 기본 모드로 무엇을 하는지 지켜보고, 익숙해지면 자동 수락을 씁니다.

컨텍스트(Context)란?

AI의 작업 기억 공간

컨텍스트 창은 AI가 한 번에 볼 수 있는 내용의 양입니다. 대화뿐 아니라 읽은 파일, 명령 결과까지 모두 여기에 쌓이고, 크기는 토큰 단위로 정해져 있습니다.

시스템 CLAUDE.md 대화 읽은 파일 · 명령 결과 남은 공간

가득 차면 오래된 내용을 요약해서 공간을 만듭니다. 이때 세부 내용이 빠질 수 있어 중요한 규칙은 CLAUDE.md에 적어 둡니다.

📌 CLAUDE.md = 프로젝트 기억

세션을 시작할 때마다 자동으로 읽히는 파일입니다. 프로젝트 구조, 실행 방법, 지켜야 할 규칙, 이미 겪은 실수를 적어 둡니다.

  • ./CLAUDE.md — 이 프로젝트용
  • ~/.claude/CLAUDE.md — 내 모든 프로젝트 공통

/init으로 초안을 만들 수 있습니다.

🧹 컨텍스트 관리 명령

  • /context — 지금 얼마나 찼는지 확인
  • /compact — 대화를 요약해 공간 확보
  • /clear — 새 작업을 시작할 때 비우기
  • @파일명 — 필요한 파일만 콕 집어 넣기

💡 컨텍스트를 잘 쓰는 법

  • 한 대화에 한 가지 작업만
  • 주제가 바뀌면 /clear
  • "전부 읽어 봐" 대신 필요한 파일·위치를 알려 주기
  • 원하는 결과와 확인 방법을 구체적으로 말하기

AI가 화면을 직접 다루는 방법

파일만이 아니라 "화면"도 다룬다

Claude Code는 기본적으로 파일과 명령을 다룹니다. 여기에 화면을 보고 클릭·입력하는 능력을 더하면, 만든 웹사이트를 직접 열어 확인하거나 구글 시트처럼 웹에서만 되는 일도 맡길 수 있습니다. 원리는 같습니다. 화면을 보고(스크린샷·페이지 구조) → 무엇을 누를지 정하고 → 마우스·키보드로 조작합니다.

🌐 Claude in Chrome

Chrome에 설치하는 브라우저 확장 프로그램입니다. Claude가 내가 쓰는 Chrome에서 탭을 열고, 페이지를 읽고, 클릭·입력·스크롤을 합니다.

  • 이미 로그인된 내 계정 그대로 작업 (구글 시트, 메일 등)
  • 사이트마다 사용 허락을 받고 동작
  • 예: 수집한 데이터를 구글 시트에 정리하기, 배포 사이트 점검

"Chrome으로 내 구글 시트를 열어서 A4부터 표를 채워 줘."

🖱️ Computer Use

브라우저를 넘어 컴퓨터 화면 전체를 다루는 기능입니다. 화면을 캡처해 보고, 마우스를 옮기고, 키보드를 눌러 데스크톱 앱까지 조작합니다.

  • 웹이 아닌 프로그램(엑셀, 설정 창, 직접 만든 앱 등)도 다룸
  • 사람이 화면을 보며 하는 일을 그대로 흉내 냄
  • 예: 만든 데스크톱 앱을 실행해 버튼이 잘 동작하는지 확인

"내가 만든 앱을 실행해서 카메라 켜기 버튼을 눌러 보고 화면이 잘 나오는지 확인해 줘."

구분다루는 범위이럴 때 쓴다
내장 브라우저Claude 앱 안의 별도 브라우저내가 만든 사이트 미리보기·확인
Claude in Chrome내 Chrome (로그인 상태 포함)로그인이 필요한 웹 서비스 작업
Computer Use컴퓨터 화면 전체웹이 아닌 데스크톱 프로그램 조작

🔐 비밀번호 입력, 결제, 계정 설정 변경처럼 민감한 일은 AI에게 맡기지 않고 사람이 직접 합니다.

🤖 Claude Code로 홈페이지 만들기

  1. 1
    폴더를 만들고 Claude Code 실행

    빈 폴더에서 claude를 실행하고, 만들고 싶은 것을 목적·대상·분위기까지 말로 설명합니다.

    "이 폴더에 바이브 코딩을 소개하는 한 페이지 사이트를 HTML/CSS/JS로 만들어 줘. 처음 배우는 사람이 대상이고, 어두운 배경의 세련된 느낌이면 좋겠어."

  2. 2
    큰 작업은 Plan 모드로 계획부터

    Shift+Tab으로 Plan 모드를 켜면 파일을 고치지 않고 계획만 보여 줍니다. 계획이 마음에 들면 승인하고 진행합니다.

    "섹션 구성과 디자인 방향을 먼저 계획해 줘."

  3. 3
    결과를 보고 말로 다듬기 (바이브 코딩)

    브라우저로 결과를 보고, 마음에 안 드는 부분을 구체적으로 말합니다. 화면 캡처를 붙여 넣어도 됩니다.

    "모바일(375px)에서 메뉴가 제목과 겹쳐. 고쳐 주고 다시 확인해 줘."

  4. 4
    CLAUDE.md로 규칙 남기기

    /init으로 CLAUDE.md를 만들고, 작업 중 알게 된 규칙과 실수를 계속 기록하게 합니다. 다음 대화에서도 같은 기준으로 작업합니다.

    "방금 겪은 문제와 해결법을 CLAUDE.md의 '주의할 점'에 적어 줘."

  5. 5
    작업이 바뀌면 컨텍스트 정리

    한 작업을 마치면 /clear로 비우고 다음 작업을 시작합니다. 중요한 내용은 이미 CLAUDE.md에 있으니 잃어버리지 않습니다.

DAY 2

배포 · MCP · Supabase · 결제 · 영상 제작

DAY 1에서 내 PC에 만든 사이트를 오늘은 인터넷에 올리고(배포), 진짜 서비스처럼 기능을 붙입니다. 외부 도구를 연결하는 MCP, 로그인·데이터 저장을 맡는 Supabase, 돈을 받는 토스 결제를 차례로 붙이고, 마지막으로 완성한 앱을 알리는 홍보영상까지 코드로 만듭니다.

배포 개념 먼저

배포

내 PC에만 있는 사이트를 인터넷 주소로 누구나 볼 수 있게 올리는 일

Git

파일이 바뀐 기록을 저장하는 도구. 저장 한 번 = 커밋(commit)

GitHub

Git 기록을 온라인에 보관하는 곳. 올리는 일 = 푸시(push)

Vercel

GitHub 저장소를 지켜보다가 push가 오면 자동으로 사이트를 다시 만들어 올려 주는 호스팅 서비스

환경 변수

API 키처럼 코드에 넣으면 안 되는 값을 서버 설정에 따로 저장하는 방법

1. GitHub 연동

  1. 폴더를 Git 저장소로 만들기
  2. 현재 파일을 커밋(기록 저장)
  3. github.com에 빈 저장소 만들기
  4. 내 폴더와 GitHub 저장소를 연결
  5. push로 기록을 올리기

명령어는 Claude Code가 대신 실행하므로 순서와 의미만 알면 됩니다.

2. Vercel 연동

  1. vercel.com 에서 GitHub 계정으로 로그인
  2. Add New → Project 에서 저장소 Import
  3. Framework Preset 확인 후 Deploy
  4. 이후 main에 push 하면 자동 재배포

🤖 Claude Code로 배포하기

  1. 1
    Git 저장소 만들고 첫 커밋

    git 명령을 몰라도 말로 맡길 수 있습니다. 올리면 안 되는 파일(.env 등)도 함께 챙겨 달라고 합니다.

    "이 폴더를 git 저장소로 만들고, .gitignore를 추가한 다음 첫 커밋 해 줘."

  2. 2
    GitHub에 저장소 만들고 push

    github.com에서 빈 저장소를 만들고(사람이 직접), 주소를 알려 주면 연결과 push를 맡깁니다.

    "https://github.com/아이디/저장소.git 에 연결해서 main 브랜치로 push 해 줘."

  3. 3
    Vercel에서 Import (한 번만)

    vercel.com에서 GitHub 저장소를 Import하고 Deploy를 누릅니다. 로그인·권한 승인은 사람이 직접 합니다.

  4. 4
    이후로는 "고치고 올려 줘"만

    수정 → 커밋 → push 하면 Vercel이 자동으로 다시 배포합니다.

    "메인 제목 문구를 바꾸고 커밋·푸시해 줘. 배포 사이트에 반영됐는지도 확인해 줘."

🔌 MCP: AI에 도구 연결하기

MCP (Model Context Protocol)

AI 모델이 외부 도구·데이터에 접근하도록 연결하는 표준 규격입니다. "AI용 USB-C"라고 생각하면 쉽습니다.

"토스페이먼츠 연동 가이드 MCP를 이 프로젝트에 연결해 줘."

연결된 서버 목록은 /mcp로 확인합니다.

실습에서 쓴 MCP 서버

  • 토스페이먼츠 연동 가이드 — 최신 결제 문서를 찾아 줌
  • Supabase — 데이터베이스 만들기·관리
  • Claude in Chrome / 내장 브라우저 — 화면 확인, 클릭, 스크린샷

🗄️ Supabase 연동하기

서버를 직접 만들지 않고 얻는 "백엔드"

HTML/CSS/JS만으로 만든 사이트는 새로고침하거나 다른 기기로 가면 데이터가 사라집니다. 회원가입, 상품·주문 저장, 여러 사람이 같은 데이터를 보는 기능에는 서버와 데이터베이스가 필요합니다. Supabase는 이것들을 서버 없이 바로 쓸 수 있게 묶어 둔 서비스입니다.

데이터베이스 (DB)

상품·회원·주문을 표(테이블) 형태로 저장하는 곳. 엑셀 시트 여러 장이 서로 연결된 모습

Auth (인증)

회원가입·로그인 기능. 이메일, Google 로그인 등을 지원

RLS (행 단위 보안)

"자기 주문만 볼 수 있다" 같은 규칙을 DB에 직접 거는 것. 공개 키가 노출돼도 데이터를 지켜 줌

🖥️ 브라우저가 하는 일: 결제 요청

  1. 클라이언트 키로 결제 위젯(결제 수단 선택 화면)을 띄움
  2. 주문 금액을 위젯에 알려 줌
  3. 손님이 결제 버튼을 누르면 토스 결제창이 열림
  4. 인증이 끝나면 성공 페이지로 돌아오며 결제 번호·주문 번호·금액을 받음

이 단계까지는 아직 돈이 빠져나가지 않습니다.

🔒 서버가 하는 일: 결제 승인

  1. 성공 페이지가 받은 정보를 서버로 보냄
  2. 서버가 DB의 주문 금액과 같은지 확인
  3. 시크릿 키로 토스에 "이 결제 확정해 줘"라고 요청
  4. 승인되면 주문을 '결제 완료'로 바꿈

이 승인 요청이 성공해야 실제로 결제가 끝납니다.

DAY 3

스킬(Skill) 생성하기

DAY 1~2에서 비슷한 요청을 여러 번 반복했다면, 이제 그 방법을 스킬로 저장할 차례입니다. 작업 순서를 SKILL.md로 묶어 두면 Claude가 필요할 때 알아서 꺼내 씁니다. 직접 만드는 방법과 남이 만든 스킬을 찾아 쓰는 방법을 함께 봅니다.

스킬 개념 먼저

스킬 = Claude에게 주는 "업무 매뉴얼"

신입에게 업무 매뉴얼을 건네듯, 특정 작업을 어떤 순서로, 어떤 도구로, 무엇을 조심하며 하는지 적어 둔 폴더입니다. 요청이 매뉴얼 설명과 맞으면 Claude가 스스로 꺼내 읽고 그대로 따릅니다.

구분무엇인가언제 읽히나이럴 때 쓴다
CLAUDE.md프로젝트 규칙·기억세션마다 항상모든 작업에 적용할 규칙
스킬특정 작업의 절차서 + 스크립트요청이 설명과 맞을 때만자주 반복하는 정해진 작업
MCP외부 도구 연결 통로도구가 필요할 때브라우저·DB·API 같은 바깥 기능

스킬은 폴더 하나

.claude/skills/스킬이름/ 폴더 안에 세 가지를 둡니다.

  • SKILL.md (필수) — 언제 쓰는지 + 어떻게 하는지
  • scripts/ (선택) — 매번 똑같이 돌릴 코드
  • references/ (선택) — 필요할 때만 펼쳐 볼 상세 자료

파일은 Claude Code가 만들어 주므로 직접 쓸 필요는 없습니다.

SKILL.md의 두 부분

  • 앞부분 (name · description) — 스킬의 이름표. "이런 요청이 오면 나를 써라"를 적음
  • 본문 — 입력은 무엇이고, 어떤 순서로 하며, 무엇을 조심해야 하는지 적은 절차서

사람에게 업무 인수인계 문서를 쓴다고 생각하면 됩니다.

동작 원리: 점진적 로딩

  1. 평소에는 name + description만 읽음
  2. 요청이 description과 맞으면 SKILL.md 본문 로딩
  3. 필요할 때만 scripts / references 파일 사용

→ 스킬을 많이 만들어도 컨텍스트를 거의 차지하지 않습니다.

💡 좋은 스킬 만들기

  • description이 가장 중요 — 언제 써야 하는지 구체적으로
  • /skill-creator로 초안 생성 후 다듬기
  • 직접 써 보며 잘 호출되는지 테스트
  • 실행 중 겪은 문제와 해결법은 SKILL.md나 references/에 바로 기록

RAG란?

Retrieval-Augmented Generation — 질문과 관련된 문서를 먼저 검색해서 프롬프트에 붙인 뒤 생성하는 방식입니다.

  • 모델이 모르는 최신·내부 데이터로 답변 가능
  • 근거가 있어 환각(hallucination) 감소
  • 모델 재학습 없이 문서만 바꾸면 됨

💻 로컬 LLM 만들기

인터넷 없이 내 PC에서 돌아가는 AI

ChatGPT·Claude 같은 AI는 회사 서버에서 돌아가서 인터넷과 비용이 필요합니다. 로컬 LLM은 공개된 모델을 내려받아 내 PC에서 직접 실행합니다. 대화 내용이 밖으로 나가지 않아 보안이 중요한 자료에 쓰기 좋지만, PC 사양에 맞는 크기의 모델을 골라야 합니다.

Ollama

공개 모델을 명령 한 줄로 내려받아 내 PC에서 실행해 주는 프로그램

모델 크기 (1.5b, 7b…)

b는 10억 개의 매개변수. 클수록 똑똑하지만 메모리(RAM)를 더 많이 씀

llmfit

내 PC 사양(CPU·RAM·그래픽)을 보고 돌릴 수 있는 모델을 점수로 추천해 주는 도구

🧠 에이전트(Agent)란?

대답만 하는 AI → 스스로 일을 끝내는 AI

RAG의 "문서 검색"도 에이전트가 쓸 수 있는 도구 중 하나입니다. RAG 챗봇에 계산·저장 같은 도구를 더하면 에이전트로 넓힐 수 있습니다.

👥 서브 에이전트(Sub-agent)란?

팀장 AI가 일을 나눠 맡기는 도우미 AI

큰 일을 혼자 다 하면 컨텍스트(작업 기억)가 금방 가득 찹니다. 그래서 Claude Code는 일부 일을 서브 에이전트에게 맡깁니다. 서브 에이전트는 자기만의 작업 공간에서 일하고, 끝나면 결과만 요약해서 돌려줍니다.

  • 역할 나누기 — "조사 담당", "디자인 검토 담당", "테스트 담당"처럼 전문 역할을 줄 수 있음
  • 동시에 일하기 — 서로 상관없는 일은 여러 서브 에이전트가 한꺼번에 진행
  • 기억 아끼기 — 긴 조사 내용은 서브 에이전트 쪽에 남고, 메인 대화엔 결론만 옴

"서브 에이전트를 써서 data 폴더의 엑셀 파일 3개를 각각 분석하고, 결과만 모아서 알려 줘."

🤖 Claude Code로 에이전트 만들기

  1. 1
    목표와 도구를 정하기

    에이전트가 무엇을 끝내야 하는지, 그러려면 어떤 도구가 필요한지 먼저 말로 정리합니다.

    "소득세 상담 에이전트를 만들고 싶어. 필요한 도구가 뭘지 같이 정리해 줘. 조문 검색, 세액 계산, 결과 저장 정도를 생각하고 있어."

  2. 2
    도구를 하나씩 만들기

    각 도구를 따로 만들어 먼저 혼자 잘 동작하는지 확인합니다.

    "기존 RAG 검색을 '조문 검색' 도구로 바꾸고, 과세표준을 넣으면 세액을 돌려주는 '세액 계산' 도구도 만들어 줘."

  3. 3
    루프로 연결하기

    "모델이 질문을 보고 필요한 도구를 골라 쓰고, 결과를 보고 다음 행동을 정하게 연결해 줘. 최대 5번까지만 반복하게 해."

  4. 4
    과정을 보이게 하고 시험하기

    에이전트가 어떤 도구를 왜 썼는지 화면에 보이게 해야 잘못된 판단을 찾을 수 있습니다.

    "답변 위에 '사용한 도구와 결과'를 단계별로 보여 줘. 연봉 5천만 원 예시로 테스트해 줘."

    듣기 → 말하기부터 연결

    AI 두뇌 붙이기

    들은 글자를 LLM에 보내 대답을 받습니다. API 키는 채팅에 붙이지 말고 설정 파일(환경 변수)에 직접 넣습니다.

    기능(도구) 더하기 → 에이전트로

    호출어와 마무리
